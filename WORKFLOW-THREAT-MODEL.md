# Workflow threat model
No `pull_request_target`, `workflow_run`, `repository_dispatch`, or privileged untrusted-code path was found in the uploaded workflows. Existing external Actions are pinned to 40-character SHAs. 111X CI starts with `permissions: {}` and grants only `contents: read` to verification. The Cloudflare bridge reads a secret token on manual/push triggers but does not check out repository code and performs a GET-only verification. Production deployment workflow is intentionally absent; therefore production environment approval/concurrency/provenance remain BLOCKED rather than claimed.
